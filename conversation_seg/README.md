# Conversation Segmentation

This folder contains the action library, prompt templates, output schema, and
results for the turn-level conversation segmentation pass.

Current design:

- The LLM labels only each Student turn's `action`.
- The script backfills `conversation_id`, Student turn `text`, and `phase`.
- The script derives contiguous `phase_segments` from the action-derived phases.
- This keeps model output compact and reduces turn-counting/phase-consistency errors.

## Preparation

Run from the repository root.

Clean the original transcripts by dropping conversations with `n_turns <= 1`:

```bash
python -m scripts.clean_transcript
```

This writes:

```text
data_prep/clean_transcript.jsonl
```

Create deterministic turn-numbered transcripts:

```bash
python -m scripts.prepare_numbered_transcripts --input data_prep/clean_transcript.jsonl --output conversation_seg/numbered_transcripts.jsonl
```

Create segmentation ID pools from the cleaned transcript IDs and the MiniMax wide coding file:

```bash
python raw_cab/prepare_segmentation_pools.py
```

This updates:

```text
raw_cab/success_attack/ids.txt
raw_cab/unsuccess_attack/ids.txt
raw_cab/no_attack/ids.txt
raw_cab/category_assignments.csv
```

## Running Segmentation

Dry run for prompt inspection, no API call:

```bash
python -m scripts.segment_conversations_with_minimax --ids 1131 1132 --dry-run --out-dir conversation_seg/results/smoke
```

Run a small explicit ID set:

```bash
python -m scripts.segment_conversations_with_minimax --ids 1131 1132 --out-dir conversation_seg/results/smoke
```

Run the cleaned successful-attack pool:

```bash
python -m scripts.segment_conversations_with_minimax --seg-success-attack
```

Run the cleaned unsuccessful-attack pool:

```bash
python -m scripts.segment_conversations_with_minimax --seg-unsuccess-attack
```

Run the cleaned no-attack pool:

```bash
python -m scripts.segment_conversations_with_minimax --seg-no-attack
```

Default output directories for the three pool shortcuts:

```text
conversation_seg/results/success_attack/
conversation_seg/results/unsuccess_attack/
conversation_seg/results/no_attack/
```

Resume after API failures:

```bash
python -m scripts.segment_conversations_with_minimax --seg-success-attack --resume
```

`--resume` skips records with `error == null` and retries records with API/model errors.
It does not automatically retry validation-only `needs_review` records.

Repair/regenerate derived outputs without calling the model:

```bash
python -m scripts.segment_conversations_with_minimax --out-dir conversation_seg/results/success_attack --repair-existing
```

## Result Files

Each result directory may contain the following files.

### `segmentations.jsonl`

Source:

- One line per conversation from the LLM segmentation run.
- The LLM returns compact `turns` records with only `turn` and `action`.
- The script adds `conversation_id`, backfilled `text`, action-derived `phase`, and derived `phase_segments`.

Purpose:

- Main source-of-truth output for segmentation.
- Use this for downstream structured analysis when nested JSON is convenient.

Entry level:

- One JSONL line per conversation.

### `turn_segments.csv`

Source:

- Flattened from `segmentations.jsonl -> llm_output.turns`.

Purpose:

- Human-readable per-turn table.
- Best file for reviewing whether each Student turn's action label is reasonable.

Entry level:

- One row per Student/user turn.

Typical columns:

```text
id, turn, text, phase, action
```

### `phase_segments.csv`

Source:

- Derived by script from contiguous runs of `phase` in `segmentations.jsonl -> llm_output.turns`.
- `phase` itself is deterministically mapped from `action`.

Purpose:

- Conversation trajectory analysis.
- Shows where a conversation moves through setup, trust building, reconnaissance, attack construction, escalation, and goal execution.

Entry level:

- One row per contiguous phase span within a conversation.

Typical columns:

```text
id, phase, start_turn, end_turn, actions, summary
```

### `validation_report.csv`

Source:

- Generated by comparing `segmentations.jsonl` against `conversation_seg/numbered_transcripts.jsonl`.

Purpose:

- Quality control report.
- Flags API failures, missing Student turns, extra turns, duplicate turns, out-of-order turns, failed text backfill, invalid actions, invalid phases, and empty required fields.

Entry level:

- One row per conversation.

Important columns:

```text
id, status, api_error, expected_user_turns, observed_user_turns
```

Status meanings:

- `ok`: structure passed validation.
- `api_error`: API/model call failed and `llm_output` is unavailable.
- `needs_review`: model returned output, but structural validation found an issue.

### `raw_responses/`

Source:

- Raw provider response for each API call.

Purpose:

- Debugging provider behavior, schema failures, and malformed responses.

Entry level:

- One JSON file per attempted conversation.

### `dry_run/`

Source:

- Created only when using `--dry-run`.

Purpose:

- Inspect exact system and user prompts before calling the LLM.

Entry level:

- `system_prompt.md`
- one `user_prompt_<id>.md` per selected conversation

## Core Inputs

### `conversation_action_library.md`

Defines valid actions and their conceptual phases.

### `segmentation_output_schema.json`

Defines the compact structured output requested from the LLM:

```json
{
  "turns": [
    {
      "turn": 2,
      "action": "Educational Framing"
    }
  ]
}
```

### `numbered_transcripts.jsonl`

Default transcript input for segmentation.

Each record includes:

```text
transcript_turns
student_turn_numbers
parsed_n_turns
parsed_n_student_turns
```
